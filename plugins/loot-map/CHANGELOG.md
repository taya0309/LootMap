## v0.18.8（2026-09-23 19:57）—— 关掉的类别在地图上彻底不显示（★ 实测通过）

- **修什么**：只勾「暗金/套装」时，其他颜色的装备以前仍会在地图上露出引擎自己画的
  X 标记（v0.18.7 甚至把它们染成了绿色）。
- **为什么之前不行**：「叫引擎别画」的两招都被证伪——
  `out2 = -1` 只挡光点、挡不住引擎自己画的标记；`out1 = 1` 根本不是"跳过的色号"，
  引擎把它当真颜色用（绿色的 X 的来历）。
- **现在的做法**：与星标完全同路——拉闸门 + 小桩在绘制口**就地返回**，整笔（含物品名字）不画。
  依据：星标管线 `siteA == shape 命中 == starsDrawn` 历来一一对应，证明"取色 → 紧接着那一笔绘制"
  就是同一件物品，闸门必被它自己那一笔消费、不会误吃别人的标记。
- **线上判据**（实测）：`hidden=756151 + 星品 6584 == skipA=762735 == shape 命中 762735`，分毫不差。
- **诊断升级**：`diag:` 行新增 `hidden= / skipA= / siteA=命中/总 / shape=命中/总`。

## v0.18.7（2026-09-23，存活 10 分钟）—— 中间版（做法错误，已废弃）

- 用「`out1` 写跳过色号 + `out2` 写 -1」压制关掉的类别。两招均无效，且 `out1=1`
  被引擎当颜色用 → **绿色的 X**。保留此条作为教训：隐藏一笔只能靠闸门/小桩，别指望写值。

## v0.18.6（2026-09-23 19:31）—— 修掉一个潜伏 6 个版本的绘制钩子 bug（重要）

- **症状**：装上插件后，地图上 **NPC 名字、门/箱子/传送点的白色十字集体消失**。
- **根因**：插在引擎绘制调用点上的手写小桩，恢复寄存器时把 **rax** 也恢复了——
  而 rax 正是钩子函数"要不要跳过这一笔"的返回值所在 ⇒ 判定被覆盖成
  "调用点当时的旧值"，引擎所有走这批调用点的绘制被成片吃掉。
  以前没被发现是因为 MapSense 自己也画那些标记；v0.18.5 换成自绘叠加层后暴露。
- **修法**：小桩不再保存/恢复 rax（251 → 235 字节），判定改回钩子的真实返回值。
- 新增小桩布局核对脚本（读源码常量 → 逐字节重放 → 反汇编核对；开发期内部工具，未随仓库公开）。

## 独立叠加层 v0.3.0 / v0.3.1（2026-09-23）—— 不依赖 MapSense（★ 实测通过）

- **v0.3.0**：独立版自己实现 MapSense 的宿主接入接口（4 个函数），主插件**一个字节不用改**，
  就把面板与星标画进我们的层；再加一个极窄的"模块名别名"钩子，主插件按老名字也能找到我们。
  装了真 MapSense 时独立版**自动完全停用**（连钩子都不装）。
- **v0.3.1**：修字体时序——第一次"叫客户端"必须发生在字体图集烘焙**之前**
  （与真 MapSense 的时机对齐），否则面板会静默退回英文。
- 实测：F7 全中文面板 + 地图星标全部正常，与装了 MapSense 时一致。

## v0.18.5（2026-09-23）—— 少装东西也能一眼看出原因

- 别人（或你换机器）**没装 MapSense** 时，面板会退回老式原生面板；
  以前日志里只有一句「native panel」，看不出根因。
  现在会明写一行 `panel fallback ... mapsense_module=0` 说明「缺 MapSense」，
  并说明**没有它就没有星标**。
- 配置文件 `loot-map.toml` 顶部也加了这段运行前提说明。

  - 「星标驻留」会把星**钉在屏幕上跟着人物跑** → 默认改为 0（只画引擎当帧报的）。
  - 面板状态不再影响星的亮度（开背包不再忽明忽暗）。
